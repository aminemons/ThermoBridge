# ThermoBridge completion package

This additive package continues the existing `aminemons/project` local checkout. It does **not** reinstall OSIC tools, a PDK, Docker, or Git. The files under `release/` do not overwrite `src/`, `rtl/` or the original execution brief. The original testbench verifies the real RTL through Icarus/cocotb; the added paired experiment is a **separate behavioural** RC compact-model simulation based on physics validation JSON.

## Contents

- `closed_loop.py`: 24 paired scenarios, six controllers/precision variants, raw CSV, deterministic seeds, honest error/energy statistics.
- `plots.py`: six plots, SVG/PNG, each associated with actual CSV/NPZ/validation inputs.
- `physical.py`: actual controller RTL synthesis-to-GDS using installed LibreLane and SKY130A; explicit nonzero DRC/LVS/timing gates, no fake results.
- `flow/config.json` and `flow/constraints.sdc`: independent flow config for the current RTL top, 100 ns clock.
- `report.py`: Markdown technical evidence report assembled from real local validation, experiment, and flow audit data.
- `runner.py`: single Python orchestrator, exact stage logs, hashed sources, cached physics only if input hashes match, mandatory pass/fail matrix.
- `tests/test_release.py`: fast added test cases.
- `Run-ThermoBridge.ps1`: uses the **existing** Docker container and project, copies generated evidence back, and produces a curated final ZIP.

## What it does *not* claim

- The RC experiments do not exercise the RTL PWM at the clock edge and do not simulate a spatial thermal field at every control tick. The existing cocotb testbench is the digital RTL verification source.
- Alternate arithmetic widths are Python-level trade-offs, **not** routed variant chips. Area, GDS, DRC and LVS are for the actual primary RTL only, if generated successfully.
- There is no transistor-level analogue macro, actual fabricated silicon, padframe, calibrated gas-sensor concentration readout, foundry signoff, or MEMS mask generated by this extension.
- Physical-flow failures remain failures. See `release_out/manifest.json` and `release_out/physical/audit.json` after execution. The original project README must not be used to infer completed results unless separately updated from those outputs.

## Invocation inside the installed OSIC tools

From `/foss/designs/thermobridge`, with the existing sky130A PDK environment loaded:

```bash
python3 -m release.runner
```

Outside the container, use the bundled PowerShell script from the existing local project folder, or the single paste command supplied in the ChatGPT answer.
